# BAREEQ website

Next.js 15 (App Router) + React 19 + TypeScript + Tailwind CSS 4 + Motion + Three.js / React Three Fiber / Drei. Arabic RTL throughout.

## Run it

```bash
npm install
npm run dev        # http://localhost:3000
npm run typecheck  # tsc --noEmit
npm run build
```

> **Status:** this source was written where package installs were blocked, so it has **not been compiled or run in a browser yet**. Only syntax, import-path and content-data checks were run. Run `npm install && npm run typecheck && npm run build` first and fix anything the compiler reports. The 3D head, GLSL rim shader and photo treatment in particular need a visual pass in a real browser.

## What changed in this revision

- **Hero:** the old floating shapes are gone. The hero is now a single 3D chrome mannequin head (`public/models/chrome-head.glb`) that follows the cursor, with a holographic GLSL rim glow on its silhouette.
- **Logo:** only the B mark is used (navbar, hero, footer), with its white background removed (`public/brand/logo-b.webp`). Originals are untouched in `Assets/`.
- **Service cards:** portfolio-style photo cards (photo, navy gradient, tilt, reflective light, holographic border). Each service photo also appears in its service page hero.
- **Colour distribution:** same palette, redistributed. Midnight navy and soft grey/white carry the page; chrome silver is the material; blue/purple/pink appear only as one glow behind the head, thin hairlines, hover rings and the metal's reflections.

## Revision 4: hero figure, opening slash, even grid

- **Hero figure:** replaced the chrome head with the armoured sword figure from the supplied screenshot, cut out to `public/hero/warrior.webp` (cutout is approximate; edges need a look in a browser). It floats, tilts toward the cursor and recedes on scroll. The old 3D head files are still in the repo but no longer used on the hero. **Check the licence of that model/image before launch**, since its source isn't known here.
- **Opening (`SlashIntro`):** the figure appears centred, a blade line cuts the screen diagonally and the two halves slide apart onto the hero. About 2.2 s, once per session, skippable (button, click, Esc), off for reduced motion, locks scroll only while it plays, with a CSS failsafe that removes it if scripts fail.
- **Services grid:** one even grid (1 / 2 / 3 columns), so six services make two rows of three instead of 1 + 2 + 3. The category now shows as the chip on each card.

## Motion

- **Chrome marquee** (`MarqueeBand`, `animations/Marquee.tsx`): tilted band at the hero/services seam, drifts by itself and speeds up or reverses with scroll velocity. Words are the three brand pillars.
- **Scroll-linked hero:** the 3D head turns away and recedes as you scroll, the headline drifts up and fades, the two chrome stars spin and drift at different speeds, and a hairline scroll cue pulses.
- **Headline reveal** (`SplitReveal`): words rise out of a mask. It splits on spaces only so Arabic letters stay joined.
- **Magnetic buttons** (`Magnetic`) on the main calls to action, and a holographic **scroll-progress** line (`ScrollProgress`).
- All of it respects `prefers-reduced-motion`.

Inspired by the *pattern* of a looping text ticker, scroll-driven hero and floating sticker accents seen on restaurant sites, re-expressed in BAREEQ's own chrome/holographic language. Colours were not taken from any reference site.

## The 3D head

`public/models/chrome-head.glb` is generated by `scripts/generate-head.mjs` (a signed-distance-field mannequin meshed with Surface Nets, no dependencies):

```bash
STEP=0.02 node scripts/generate-head.mjs     # regenerate (smaller STEP = denser mesh, bigger file)
```

It is a stand-in modelled to match the chrome-head reference. To use a better model, drop any GLB (a head or bust) at `public/models/chrome-head.glb`; the site reads its first mesh and re-skins it with the shared chrome material.

## Photos

Service and showcase photos are hot-linked from Unsplash's CDN (`src/lib/images.ts`, configured in `next.config.ts`). They were picked from Unsplash search results by description and **have not been looked at in a browser yet**, so check each one. If a photo fails to load, the card falls back to dark holographic artwork. Swap any of them for the brand's own work by changing `image.src` in `src/data/services.ts` and `media.src` in `src/data/showcase.ts` to a file under `public/`. The showcase tiles are labelled "معاينة مفهومية" (concept preview) because they are not client work.

## What to configure (nothing is invented)

Everything lives in `src/data/`:

| File | What to fill in |
|---|---|
| `site-config.ts` | `siteUrl` (enables canonical URLs + sitemap), contact email/phone/WhatsApp, social links, **`contact.formEndpoint`** (required for the form to actually send), `paymentProvider` |
| `services.ts` | All copy, photos, features, steps, benefits, FAQs and plans for the 6 services |
| `pricing.ts` | Plan type + `CONTACT_FOR_PRICING` text. In `services.ts`, set `price: { monthly: "…", yearly: "…" }` on a plan to show a price |
| `showcase.ts` | Swap in real work and set `concept: false` |

Defaults: no prices (shows "تواصل معنا لمعرفة تفاصيل الاشتراك"), no contact details, no social links, no payment. Subscribe buttons go to the contact form until a payment provider is configured. The contact form validates, then states clearly that nothing was sent while no endpoint is configured.

## Structure

- `src/app`: `/`, `/about`, `/contact`, `/services/[slug]` (6 static pages from one template)
- `src/components/three`: chrome material + procedural studio environment, GLSL holographic material, chrome head, hero scene, WebGL fallback
- `scripts/`: head generator
- `Assets/` (brand originals) and `Reference/` (inspiration) are kept untouched
